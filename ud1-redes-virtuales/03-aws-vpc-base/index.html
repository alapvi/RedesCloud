    Amazon VPC · Construcción de una red virtual en AWS¶

    1. Objetivo¶

    Construiremos nuestra primera infraestructura de red en AWS:

    1 VPC
2 subnets
2 Route Tables
1 Internet Gateway
2 instancias EC2

    Queremos comprender:

    1. cómo se define un espacio de direccionamiento;
    2. cómo se divide mediante subnets;
    3. cómo decide AWS el camino de un paquete;
    4. qué convierte una subnet en pública;
    5. qué condiciones necesita una instancia para comunicarse con Internet.

    Una VPC es un dominio de routing definido mediante direccionamiento, subnets, rutas y gateways.

    2. Arquitectura¶

                             INTERNET
                             │
                    Internet Gateway
                             │
        ┌────────────────────┴────────────────────┐
        │             VPC 10.0.0.0/16             │
        │              VPC Router                 │
        │                                         │
        │ PUBLIC SUBNET              PRIVATE SUBNET
        │ 10.0.1.0/24                10.0.2.0/24  │
        │      │                          │       │
        │ EC2-PUBLIC                 EC2-PRIVATE  │
        └─────────────────────────────────────────┘

    3. Region y Availability Zone¶

    Una VPC es un recurso regional. Cada subnet pertenece a una única Availability Zone.

    En esta UD utilizaremos una única AZ para centrarnos en networking.

    4. VPC¶

    Usaremos:

    10.0.0.0/16

    Las subnets deberán estar contenidas en este rango.

    5. Diseño de direccionamiento¶

    10.0.1.0/24 → Public Subnet
10.0.2.0/24 → Private Subnet

    No se solapan y dejan espacio para crecimiento.

    6. Direcciones reservadas por AWS¶

    AWS reserva las cuatro primeras y la última dirección IPv4 de cada subnet.

    Para 10.0.1.0/24:

    Dirección Uso
    10.0.1.0 red
    10.0.1.1 router de VPC
    10.0.1.2 DNS de AWS
    10.0.1.3 reservado
    10.0.1.255 reservado

    Una /24 proporciona 251 direcciones utilizables.

    7. Router implícito de VPC¶

    AWS proporciona un router implícito. Su comportamiento se controla principalmente mediante Route Tables.

    Public Subnet
      │
      ▼
  VPC Router
      ▲
      │
Private Subnet

    8. Route Tables¶

    Una regla tiene:

    Destination → Target

    Por ejemplo:

    10.0.0.0/16 → local
0.0.0.0/0   → Internet Gateway

    9. Ruta local¶

    AWS incorpora automáticamente:

    10.0.0.0/16 → local

    Esto permite routing interno dentro del espacio de la VPC, sujeto a las políticas de seguridad.

    10. Longest Prefix Match¶

    Si varias rutas coinciden, se utiliza la más específica.

    10.0.0.0/16 → local
0.0.0.0/0   → IGW

    Para 10.0.2.30 se selecciona /16, no /0.

    11. Main Route Table¶

    Toda VPC dispone de una Main Route Table. Una subnet sin asociación explícita utiliza esa tabla.

    En nuestros laboratorios haremos asociaciones explícitas:

    public-subnet  → rt-public
private-subnet → rt-private

    12. Internet Gateway¶

    Un IGW es un componente gestionado por AWS que actúa como target de routing hacia Internet.

    Crear y asociar un IGW no proporciona automáticamente Internet.

    13. Subnet pública¶

    rt-public:

    10.0.0.0/16 → local
0.0.0.0/0   → IGW

    La presencia de una ruta hacia el IGW convierte la subnet en pública desde el punto de vista del routing.

    14. Subnet privada¶

    rt-private:

    10.0.0.0/16 → local

    No tiene salida directa a Internet.

    15. Público y privado son propiedades de routing¶

    Una subnet no se convierte en pública por su nombre ni porque una EC2 tenga IP pública.

    La diferencia fundamental es:

    PUBLIC:  0.0.0.0/0 → IGW
PRIVATE: sin ruta → IGW

    16. EC2 y ENI¶

    Una EC2 se conecta a la VPC mediante una Elastic Network Interface (ENI):

    EC2
 │
 ▼
ENI
 │
 ▼
Subnet
 │
 ▼
VPC

    La ENI es relevante para direccionamiento, MAC y Security Groups.

    17. IPv4 pública e Internet Gateway¶

    Dentro del SO invitado veremos normalmente la IPv4 privada. Para IPv4 pública, AWS realiza lógicamente una traducción 1:1 en el IGW entre la IP pública y la privada asociada.

    Para acceso IPv4 directo mediante IGW necesitamos:

    IP pública o Elastic IP
+
ruta hacia IGW
+
política de seguridad compatible

    18. Security Group¶

    En esta UD se introduce únicamente como control básico de tráfico sobre la interfaz.

    Usaremos reglas sencillas para SSH, ICMP y HTTP. La comparación SG/NACL/firewall se reserva para la UD2.

    20. Caso B · EC2 pública → EC2 privada¶

    Se utiliza:

    10.0.0.0/16 → local

    El IGW no participa.

    21. Caso C · EC2 privada → Internet¶

    rt-private solo contiene:

    10.0.0.0/16 → local

    No existe ruta válida hacia Internet. La comunicación debe fallar.

    22. ¿Por qué no usamos NAT Gateway todavía?¶

    Queremos separar:

    ¿Existe routing hacia Internet?

    de:

    ¿Cómo damos salida a una red privada sin exponerla?

    La UD1 resuelve lo primero; NAT se estudiará en UD2.

    23. Tabla de comportamiento esperado¶

    Origen Destino Ruta Resultado
    Public EC2 Private EC2 10.0.0.0/16 → local ✅*
    Private EC2 Public EC2 10.0.0.0/16 → local ✅*
    Public EC2 Internet 0.0.0.0/0 → IGW ✅*
    Private EC2 Internet no existe ❌

    * Siempre que las políticas de seguridad permitan el tráfico.

    24. Routing y seguridad son problemas distintos¶

    Que exista un camino no significa que el tráfico esté permitido.

    25. Errores conceptuales a evitar¶

    Subnet pública

    No es pública porque una máquina tenga IP pública, sino porque la Route Table contiene una ruta hacia un IGW.

    Internet Gateway

    Crear un IGW no da Internet automáticamente a toda la VPC.

    Subnet privada

    Una subnet privada puede comunicarse con otras subnets de la VPC mediante la ruta local.

    Tablas de rutas

    ip route dentro de Linux y una VPC Route Table son niveles distintos.
