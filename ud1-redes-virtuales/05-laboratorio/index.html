    Laboratorios · UD1¶

    Los laboratorios siguen el ciclo:

    Predecir → configurar → comprobar → explicar

    Laboratorio 1 · Direccionamiento IPv4 y CIDR¶

    Analizar:

    10.20.30.15/24

    y determinar host, red, máscara, número total de direcciones, rango de hosts y broadcast.

    Después analizar:

    10.20.34.15/20

    para evitar asumir fronteras /24.

    Laboratorio 2 · Red aislada en Proxmox¶

    Arquitectura:

    VM-A 192.168.50.10/24
        │
      vmbr1
        │
VM-B 192.168.50.20/24

    Características:

    Router:   no
Gateway:  no
Internet: no
VLAN:     no

    Crear vmbr1 sin IP ni puerto físico, conectar ambas VM y validar:

    ip -br addr
ip route
ping -c 4 192.168.50.20
ip neigh

    Laboratorio 3 · Romper la conectividad¶

    Cambiar VM-B a:

    192.168.60.20/24

    Responder:

    1. ¿Funciona el bridge?
    2. ¿Comparten dominio Ethernet?
    3. ¿Comparten red IP?
    4. ¿Qué elemento falta?

    Conclusión: compartir capa 2 no elimina la necesidad de routing entre redes IP distintas.

    Laboratorio 4 · Construcción manual de VPC¶

    Crear:

    VPC: 10.0.0.0/16
public-subnet:  10.0.1.0/24
private-subnet: 10.0.2.0/24

    Convención:

    rc-ud1-vpc
rc-ud1-public-subnet
rc-ud1-private-subnet
rc-ud1-rt-public
rc-ud1-rt-private
rc-ud1-igw
rc-ud1-public-ec2
rc-ud1-private-ec2

    Laboratorio 5 · Routing de VPC¶

    Crear las Route Tables y asociarlas explícitamente:

    public-subnet  → rt-public
private-subnet → rt-private

    Observar:

    10.0.0.0/16 → local

    Laboratorio 6 · Internet Gateway¶

    Crear rc-ud1-igw, asociarlo a la VPC y añadir solo a la tabla pública:

    0.0.0.0/0 → IGW

    Laboratorio 7 · Instancias EC2¶

    Crear:

    rc-ud1-public-ec2
Private IPv4: sí
Public IPv4:  sí

    y:

    rc-ud1-private-ec2
Private IPv4: sí
Public IPv4:  no

    Laboratorio 8 · Validación del recorrido¶

    Public EC2 → Internet¶

    EC2 → rt-public → 0.0.0.0/0 → IGW → Internet

    Public EC2 → Private EC2¶

    10.0.0.0/16 → local

    Private EC2 → Internet¶

    Debe fallar porque rt-private no tiene una ruta de salida.

    Matriz final¶

    Origen Destino Ruta utilizada Esperado Resultado
    public-ec2 private-ec2 10.0.0.0/16 → local ✅
    private-ec2 public-ec2 10.0.0.0/16 → local ✅
    public-ec2 Internet 0.0.0.0/0 → IGW ✅
    private-ec2 Internet ninguna ❌

    Evidencias mínimas¶

    1. Diagrama.
    2. Tabla de direccionamiento.
    3. Subnets.
    4. Asociaciones subnet–Route Table.
    5. Route Tables.
    6. IGW.
    7. Direcciones EC2.
    8. Matriz de conectividad.
    9. Explicación del caso que no funciona.

    Limpieza¶

    Eliminar en orden inverso:

    EC2
 ↓
Internet Gateway
 ↓
Route Tables personalizadas
 ↓
Subnets
 ↓
VPC
