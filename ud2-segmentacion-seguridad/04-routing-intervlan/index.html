    Routing inter-VLAN¶

    Segmentar separa redes. Enrutar permite que esas redes se comuniquen.

    1. Punto de partida¶

    WEB → 10.10.10.10/24 → GW 10.10.10.1
APP → 10.10.20.10/24 → GW 10.10.20.1
DB  → 10.10.30.10/24 → GW 10.10.30.1

    OPNsense participa directamente en las tres redes.

    2. Decisión del host origen¶

    WEB quiere alcanzar 10.10.20.10.

    WEB compara el destino con su prefijo 10.10.10.0/24 y determina que no es local.

    Por tanto usa:

    default gateway → 10.10.10.1

    Comprobamos la decisión con:

    ip route
ip route get 10.10.20.10

    3. ARP al siguiente salto¶

    WEB no necesita inicialmente la MAC de APP. Necesita la MAC de su gateway.

    ip neigh

    Conceptualmente:

    10.10.10.1 → MAC_OPNSENSE_WEB

    4. Trama y paquete¶

    Primera trama Ethernet:

    MAC origen  = WEB
MAC destino = OPNsense VLAN10

    Paquete IP:

    src = 10.10.10.10
dst = 10.10.20.10

    OPNsense recibe la trama, procesa el paquete IP y consulta su tabla de routing.

    5. Longest Prefix Match¶

    Si existen:

    10.10.0.0/16
10.10.20.0/24

    para 10.10.20.10 gana /24 porque es más específica.

    Este principio se aplica tanto en routing convencional como más adelante en AWS Route Tables.

    6. Nueva trama en la red destino¶

    OPNsense selecciona VLAN20, resuelve por ARP la MAC de APP y construye una nueva trama:

    MAC origen  = OPNsense VLAN20
MAC destino = APP

    El paquete IP conserva:

    10.10.10.10 → 10.10.20.10

    salvo campos como TTL.

    El paquete IP atraviesa el router; la trama Ethernet no.

    7. TTL y traceroute¶

    Cada router decrementa TTL.

    64 → 63

    Cuando TTL llega a 0, el router descarta el paquete y puede generar ICMP Time Exceeded.

    traceroute utiliza este comportamiento para descubrir saltos.

    8. Misma red frente a red distinta¶

    Misma red¶

    WEB 10.10.10.10
WEB-02 10.10.10.20

    ARP destino → entrega directa

    Red distinta¶

    WEB 10.10.10.10
APP 10.10.20.10

    ARP gateway → router → ARP destino

    9. Qué es realmente el gateway¶

    El default gateway no es “la dirección para Internet”.

    Es el siguiente salto que utiliza el host cuando el destino no está directamente conectado.

    Por eso WEB envía tanto APP como 8.8.8.8 inicialmente a 10.10.10.1.

    10. Reachability ≠ Authorization¶

    Podemos tener:

    ruta correcta + firewall bloqueando

    O:

    firewall permisivo + sin ruta

    Que exista un camino no significa que el tráfico esté permitido.

    11. Ruta de retorno¶

    Una conexión necesita ida y vuelta:

    WEB → OPNsense → APP
APP → OPNsense → WEB

    Si APP recibe el paquete pero no dispone de gateway, la ida puede existir y la comunicación completa fallar.

    12. Fallo: máscara incorrecta¶

    Configura temporalmente:

    WEB 10.10.10.10/8

    WEB puede considerar 10.10.20.10 como destino local y realizar ARP directamente en VLAN10.

    ip route get 10.10.20.10

    permite ver la decisión errónea.

    13. Fallo: gateway incorrecto¶

    default via 10.10.10.254

    WEB podrá seguir hablando con hosts de su propia subnet, pero fallará hacia otras redes.

    14. Fallo: APP sin ruta de retorno¶

    APP recibe tráfico pero no sabe cómo devolverlo a 10.10.10.0/24.

    Esto demuestra que “el paquete llega” no implica que la conexión funcione.

    15. Captura por puntos¶

    En WEB:

    tcpdump -ni ens18

    En OPNsense capturamos en WEB y APP.

    En APP:

    tcpdump -ni ens18

    Podemos responder:

    ¿sale del origen?
¿entra al router?
¿sale del router?
¿llega al destino?
¿vuelve la respuesta?

    16. Procedimiento de troubleshooting¶

    1. IP origen
2. máscara
3. ip route get
4. gateway
5. reachability gateway
6. route en OPNsense
7. estado destino
8. firewall
9. servicio
10. retorno

    Herramientas:

    ip -br addr
ip route
ip route get DESTINO
ip neigh
ping
traceroute
tcpdump

    Idea clave¶

    VLAN → crea fronteras L2
ROUTING → crea caminos L3
FIREWALL → controla quién puede usar esos caminos

    La segmentación crea fronteras. El routing crea caminos.
